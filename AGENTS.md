# Правила автономной разработки

1. При новом запуске **сначала** прочитай `.ai/HANDOFF.md` и `.ai/CURRENT_TASK.md`, затем относящиеся к текущей задаче документы. Не сканируй заново весь репозиторий.
2. Все изменения только в `Arthur200014/looping`; `Arthur200014/testing-hosting` **READ ONLY**.
3. Перед записью проверь HEAD `main`, состав изменений и актуальность документации. Никакого force-push. Коммить только завершённый проверяемый этап.
4. Архитектура и инварианты: `.ai/PROJECT_SPEC.md`, `.ai/DECISIONS.md`, `docs/ARCHITECTURE.md`.
5. Математика: проверяй условие, ответы, шаги, рисунки, уровень и источник каждой задачи. Не приписывай авторские задачи ФИПИ.
6. Проверки фиксируй в `.ai/TEST_RESULTS.md`. Не называй браузерную или двухклиентскую синхронизацию проверенной без реального выполнения.
7. Каждый инкремент: одна ограниченная задача → реализация → детерминированные тесты → браузерные/двухклиентские тесты при наличии изменений UI/realtime → правки → обновление `.ai/*`.
8. Нельзя массово генерировать комплекты №1–25 до прохождения quality gate общего ядра и эталонного №13.
9. Изолируй учебный контент, темы, механики, realtime transport, состояние, рисование и persistence. Не копируй гигантские legacy HTML.
10. Не подключай production БД/сервис и не вставляй ключи, пароли, рабочие ID или URL старой системы. Секреты не коммитить.
11. В отчёте обязательно: STATUS, STAGE, TASK, COMPLETED, FILES, TESTS, GIT, PROBLEMS, NEXT_ACTION, HANDOFF.
