# PROJECT SPEC — ОГЭ интерактив №1–25

Версия: 2026-10-22. Статус проекта: архитектурный каркас, без готовых учебных комплектов.

## Задача
В `looping` создать 25 методических комплектов (№1–25): `gaid.html`, `dz1.html`, `dz2.html`, `checklist.html`, дополнительные игры по потребности. Результат должен быть пригоден для индивидуального и парного занятия с общим состоянием без перезагрузок. `testing-hosting` — источник методики для чтения, не цель записи.

## Дидактический контракт
- Гайд: короткие главы/станции: смысл → объяснённый пример → управляемая практика → без подсказок → типичные ошибки → рефлексия → итог.
- Каждая станция: цель/умение, проверяемый математический ответ (когда применимо), ошибка и объяснение, подсказки по ступеням и их учёт.
- ДЗ: смысловые прототипы, несколько независимых наборов; повтор только для интервального закрепления, не простая замена чисел. Показывать подробный разбор после допустимой попытки.
- Чек-лист: конкретные проверяемые навыки, доказательства освоения, слабые места, рекомендации по повтору; не выдавать «освоено» только по факту открытия.
- 2-я часть: полное решение/доказательство и отдельное решение преподавателя по критериям; оценка автоматически не считается экспертной.
- Источники: перед публикацией сверять демоверсию, спецификацию и критерии актуального года на официальных ресурсах ФИПИ; фиксировать URL, дату и редакцию. Материалы собственного сочинения помечать «авторская задача».
- Формулы: MathJax/LaTeX, дроби `\\frac`; геометрия — параметрически точные SVG/Canvas, соответствие условию проверять отдельно.

## UX
Темы мультяшные, тематические и собственные/с разрешёнными ассетами. Единая крупная типографика, адаптивность от мобильного до ноутбука, доступность по клавиатуре, отсутствие перегруженных экранов. Компактная горизонтальная панель доски и компактный индикатор подключений; режим скриншота не должен ломать сессию. Текст и тема не изменяют логику оценивания.

## Совместная сессия — обязательные инварианты
- Состояние комнаты разделено на navigation (chapterIndex включает 0; stationId), answers, interactions (choice, drag, match, reset, feedback), board, participants, game/progress.
- Учитель инициирует переходы; ученик видит тот же раздел без full reload; личные ответы участников не смешиваются с общими действиями.
- Для событий: `roomId`, `sessionId`, `eventId`, `actorId`, `revision`, `timestamp`, `type`, `payload`, `schemaVersion`. Серверная проверка прав, дедупликация, порядок/восстановление snapshot.
- Локальный UI обновляется оптимистично только там, где возможен откат; не создавать realtime-подписки на каждом переключении главы.
- Список активных подписок/слушателей имеет явный cleanup/dispose; переходы не увеличивают их количество.
- Общая доска: векторные штрихи с ID, шириной, цветом, точками; ластик удаляет пересечённые штрихи по ID; Undo отменяет свой последний действительный штрих; clear/reset — версионированные операции.
- Отправка прогресса/оценок идемпотентна, контроль повторных попыток — серверный, не только localStorage.
- Два независимых браузерных клиента обязательны для подтверждения синхронизации.

## Границы
Сейчас стадия A. Ни производственные базы, ни реальные ученики/данные, ни рабочий Firebase-проект не подключаются. Использовать mock/in-memory для первых тестов; реальный транспорт только с явно выделенным тестовым окружением. Политика авторизации учителя и ученика проектируется до реального доступа.

## Этапы и критерии
A. Аудит и структура: есть точная инвентаризация, документы, каталоги, текущая задача; крупные legacy файлы могут остаться с NOT_VERIFIED.
B. Ядро: state store, schema, navigation, math input, mechanics, board, transport interface, theme; тесты контрактов, без реальной БД.
C. №13 — целиком: гайд + минимум 2 ДЗ + чек-лист + мини-игра на повторно используемом ядре.
D. Независимая проверка №13: математика, разные устройства, два изолированных клиента, плохая сеть, restart, Ctrl+Z, ластик, глава 0, нагрузка на переключения.
E. Номера 1–12,14–25 — последовательно после acceptance; не копипаста.
F. Регрессия всех 25 комплектов, документация/отчёты/экзаменационная сверка.

Готовность любого номера требует одновременно: комплект, математический review, browser check, независимую проверку синхронизации, обновлённый task board. Статус NOT_VERIFIED нельзя заменить предположением.
